# MeiloX 分阶段优化计划

状态：用户已确认计划并于 2026-10-15 授权逐步实施。执行记录见 [optimization-baseline.md](optimization-baseline.md)；发布仍须单独授权。

## 已确认的目标与约束

- 优先级：播放与歌词正确性，其次操作流畅度与后台资源消耗，最后代码维护成本。
- 保留现有界面、功能、用户设置、歌单、歌词编辑数据及播放恢复行为。缺陷修复造成的行为变化须单独说明。
- 必须包含自动化测试、真机回归和性能基线；允许增加仅在调试构建启用的性能观测。
- 设置读取先迁移播放操作、页面初始化等主线程路径，再分批迁移其他调用；受 Media3 同步接口约束的位置单独评估。
- 新增或修改代码的相关测试必须通过，不得新增 lint 问题；已有问题登记影响与处理期限，播放正确性及数据丢失问题阻断发布。
- 核心类拆分与导航治理纳入本计划，排在正确性修复之后；保持单 Gradle 模块，不更换技术栈。
- 规划时尚未执行构建、测试或性能测量；实施后的实际结果以执行记录为准。下述性能问题是静态代码风险，不等于已证实的瓶颈。

## 已核实的代码依据

| 位置 | 事实 | 对计划的影响 |
| --- | --- | --- |
| `utils/DataStore.kt` | 同步 getter 使用 `runBlocking(Dispatchers.IO)` | 调用线程仍等待；主线程调用应迁移到异步读取或已加载设置快照 |
| `playback/PlayerConnection.kt` | 上一首和播放模式操作同步读取设置；多个状态直接暴露为 MutableStateFlow | 优先检查点击路径；收紧写入口并确认状态联动 |
| `data/network/ResponseHandler.kt` | safeApiCall 捕获 Exception，包含协程取消异常 | 取消必须传播，不能变成普通业务失败 |
| `utils/lyric/LyricManager.kt` | 已有加载会话标识、取消控制与部分取消异常重抛，也仍存在宽泛异常捕获 | 基于已有防串歌机制补齐，避免重复实现 |
| `ui/screen/NavigationBuilder.kt` | 同时存在旧 NavGraphBuilder 注册和新 navigationEntry 分发 | 先查调用关系，再处理重复定义与参数解析 |
| `MainActivity.kt`、`MusicService.kt`、`LyricManager.kt` | 分别约 1250、1000、1150 行，跨多项职责 | 在行为测试建立后按职责提取，文件行数不作为验收目标 |
| `.github/workflows/main.yml` | 构建步骤显式执行 assembleRelease，未显式运行单元测试或 lint | 增加可诊断的验证步骤，并确认发布依赖关系 |

## 阶段 0：建立可比较的基线

交付：环境清单、现有失败清单、场景基线及可重复验证命令。

1. 确认 JDK、Gradle、SDK、NDK/CMake、离线依赖和 arm64 构建要求；记录机器环境，不记录凭据。
2. 尝试现有单元测试、调试构建及 lint；区分环境失败、已有代码失败和本次引入失败。
3. 选取固定曲目、队列、歌词样本与网络条件。记录冷启动/热启动、首次播放、缓存播放、连续切歌、歌词加载、后台播放及 AutoMix 场景。
4. 使用请求/加载会话标识关联调试事件；不记录 Cookie、完整签名 URL 或其他认证信息。
5. 记录样本数量、设备、系统、温度/供电条件、构建类型及测量方法；性能数据记录中位数和尾部延迟，避免单次结果定结论。

验收：基线可复现；测试结果和未覆盖项明确。性能改善阈值待基线完成后制定，不预先承诺任意百分比。

本地只读核查结果（2026-10-15）：Wrapper 为 Gradle 9.6.0，配置要求 JDK 21，但 JAVA_HOME 指向 JDK 17，尚未定位可用的 JDK 21。SDK 位于 `D:\Java\AndroidSdk`，包含 platform 37、CMake 3.22.1、NDK 28.2.13676358 与 adb；当前环境未配置 SDK 环境变量，根目录无 local.properties。具体工具链兼容性须运行验证。CI 使用动态 `gradle-version: current`，改为仓库 Wrapper 以保证版本一致。

已有 64 个本地单元测试 Kotlin 文件、4 个仪器化测试文件。历史报告为 63 个 suite、381 个测试通过，最新时间为 2026-10-09，仅作历史参考。现有 PlaybackPerformanceTest 主要验证功能策略，不能替代性能基线。当前仅支持 arm64-v8a；真机验证使用 Android 13+ arm64 设备。仪器化音频测试的权限、实际声音输出及设备状态须在执行前确认。

## 阶段 1：取消与异步结果正确性

依赖：阶段 0 中相关测试能够运行，或环境限制已有明确记录。

1. safeApiCall 优先重抛 CancellationException；保持普通网络失败的现有返回约定。
2. 审查本次涉及的歌词、搜索和播放请求中的 catch/runCatching；对超时区分本次局部超时与外层任务取消。
3. 核查取消后仍可能返回的结果是否受加载会话标识保护，避免旧歌曲歌词或旧搜索结果覆盖当前内容。
4. 保留已有 LyricLoadSession 能力，不另建一套平行会话状态。

验证：父任务取消向上传播；A 请求晚于 B 返回时不能覆盖 B；取消不出现普通失败提示；局部来源失败仍可使用其他来源。测试使用可控挂起点与延迟响应，不依赖真实外网。

## 阶段 2：设置读取与响应性

依赖：阶段 1。分批迁移，先处理主线程路径。

1. 盘点同步 getter 的调用线程与频次，区分 UI/播放器事件、后台数据源解析及一次性初始化。
2. 为高频设置提供集中、可注入的 Flow/StateFlow 读取入口；保留既有偏好键、取值和默认值。
3. 显式表达设置尚未加载与加载失败的状态，防止冷启动暂用默认值就执行错误播放行为。
4. UI/播放器点击路径读取已就绪快照；需要持久化的一次性读取使用 suspend。
5. 明确写入后生效时点、连续写入次序及持久化失败反馈，避免仅为界面立即变化而隐藏保存失败。
6. 不机械替换所有 runBlocking：Media3 同步数据源回调等受接口约束的位置单独评估线程与阻塞边界。

验证：上一首与播放模式操作无同步磁盘等待；设置变化可生效；冷启动恢复正确；旧安装设置不丢失；快速连续操作下最终设置与持久化一致。

## 阶段 3：播放状态与生命周期

依赖：阶段 2。

1. PlayerConnection 对外暴露只读 StateFlow，内部保留唯一写入入口；先查明现有外部写入再调整。
2. 针对歌曲、队列索引、随机顺序等必须一致的信息，评估是否用一次 Player.onEvents 更新关联快照。
3. 保留进度与歌词动画的独立更新节奏，避免高频进度导致整页状态重建。
4. 审查页面与后台服务各自的收集生命周期：页面按可见性收集，后台播放及歌词共享保持服务生命周期。
5. 核查服务重连、播放器恢复和页面退出时的监听器/Job 清理。

验证：拖动、插队、随机播放、占位条目补全、切换音质及恢复队列时，当前歌曲与选中索引一致；UI 退出后后台播放及歌词共享继续正常；反复进入页面无重复监听。

## 阶段 4：核心职责提取

依赖：阶段 1—3 的相关验证通过。

1. MainActivity 提取应用界面容器、服务连接和剪贴板链接处理；保留导航与播放器的现有交互契约。
2. MusicService 提取媒体源工厂、播放快照恢复及历史记录协调；保留其 Android 服务与媒体会话入口职责。
3. LyricManager 提取来源调度、选择/合并策略和缓存/用户覆盖读写；先确定状态所有权，避免拆成相互修改状态的对象。
4. 每次提取一项职责，保持双播放器、AutoMix、FFmpeg 选择及音频处理链行为。

验收：每批变更可独立验证与回退；调用关系更清楚；不以新增类数量或减少行数代替收益；不伴随无关格式化。

## 阶段 5：导航与参数契约

依赖：阶段 4 中导航相关提取完成，或确认可独立处理。

1. 查明旧 NavGraphBuilder 的调用者及兼容入口，仅删除确认无使用的部分。
2. 统一路由定义与目标页面映射，减少两个注册表同步维护。
3. 评估带类型路由；迁移前确认现有返回栈恢复、SavedStateHandle 传值、顶部标签切换及特殊字符参数。
4. 为无效 ID、缺失参数和编码错误定义可恢复行为，保留有效路径的现有表现。

验证：中文、空格、斜杠、百分号等参数；重复进入同一详情页；返回与预测返回；配置变化及进程恢复；歌单、搜索、文件夹入口。

## 阶段 6：持续验证与收尾

CI 接入应在阶段 0 后尽早完成，不必等其余阶段结束；最终在本阶段汇总。

1. 增加明确的单元测试和 lint 步骤，分别输出测试报告与诊断产物。
2. 使用无发布凭据的验证 job，在 PR/push 上执行 Wrapper、单元测试与 lint；保留 APK 构建与签名流程。发布依赖验证通过，相关测试失败、新增 lint 问题、播放正确性回归或数据丢失均阻断发布。已有问题登记范围和处理期限，不新增无边界豁免。
3. 对已有 lint 问题采用有边界的基线策略，明确禁止新增的问题；不以全局忽略或跳过测试使 CI 通过。
4. 汇总每阶段真机结果、前后性能对比、未解决问题和回退方式。

## 真机回归清单

- 冷启动与进程被回收后的队列、进度、播放模式及设置恢复。
- 快速连续切歌、重复曲目、插队/删除/拖动队列、FM 补充与随机播放。
- 本地文件、下载歌曲、完整缓存、网络音源与音质降级；断网、重连和签名 URL 失效。
- 自定义歌词、本地旁置歌词、缓存及多来源切换；翻译、音译、逐字时间和用户偏移。
- 进度条与歌词跳转、全屏/迷你播放器、画中画、系统媒体控制及歌词共享。
- 锁屏、应用退到后台、音频焦点变化、耳机断开及定时停止。
- AutoMix 开关、双路交叠期间切歌/暂停/拖动、EQ 与响度均衡切换。
- 旧版本安装数据升级后设置、歌单、歌词编辑数据及播放恢复不丢失。

## 每批交付和回退

每批记录问题、修改边界、用户可见变化、验证证据、剩余风险与回退方式。默认避免数据库迁移和偏好键变更；确有必要时先提出独立方案。性能回退、数据丢失或播放正确性回归时停止推进依赖阶段，回退对应批次。

## 建议交付批次

| 批次 | 范围 | 完成条件 |
| --- | --- | --- |
| A | 环境与现状基线 | 当前提交的构建、测试及 lint 结果可追溯；环境限制明确 |
| B | CI 验证与报告 | PR/push 使用 Wrapper 验证；发布正确依赖验证结果 |
| C | safeApiCall 与取消传播 | 取消、错误与晚到结果回归通过 |
| D | 播放主线程设置读取 | 上一首、模式切换和初始化不再同步等待设置读取 |
| E | 剩余设置调用盘点与分批治理 | 调用有线程依据；剩余同步边界有明确理由与测量 |
| F | 只读播放状态与生命周期 | 外部写入迁移完毕；队列和歌曲状态一致；无重复监听 |
| G | MainActivity 职责提取 | 界面、导航、服务连接与画中画回归通过 |
| H | MusicService 职责提取 | 恢复、音源、历史、后台控制及 AutoMix 回归通过 |
| I | LyricManager 职责提取 | 自定义覆盖、多源、偏移、取消与预加载回归通过 |
| J | 导航定义与参数治理 | 有效路由行为兼容；无效参数可恢复；返回栈验证通过 |

批次大小按实际 diff 与验证成本调整；任何批次失败先处理再推进依赖批次。B 可在 A 后立即推进，性能复测应贯穿相关批次。尚无可靠执行时长，不将经验估计写成工期承诺。

## 验证命令

先定位可用的 JDK 21 并设置当前会话 JAVA_HOME；必要时遵循权限流程安装或配置，不改业务代码绕过工具链要求。在项目根目录执行：

```powershell
$env:ANDROID_HOME = 'D:\Java\AndroidSdk'
.\gradlew.bat --version
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest
& 'D:\Java\AndroidSdk\platform-tools\adb.exe' devices -l
.\gradlew.bat :app:connectedDebugAndroidTest
.\gradlew.bat :app:assembleRelease
```

命令是计划中的检查入口，未在本次规划中执行。真机缺席时可以完成独立的代码、构建及单元验证，但真机验收仍标记未完成。签名构建成功不等于获准发布。
