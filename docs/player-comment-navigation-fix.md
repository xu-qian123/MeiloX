# 评论覆盖层与歌词返回

2026-10-20。用户报告进入评论或返回时偶尔落到媒体库，随后明确要求：
评论覆盖显示，底下播放器保持展开；关闭后保留原来的播放页/歌词页。

## 最终实现

- 播放器的“更多 → 评论”切换到 `OverlayState.Comments`，不再修改主导航栈，
  也不再调用播放器的收起方法。
- `PlayerPageOverlay` 用独立全屏 Dialog 承载评论，拥有独立的导航栈和每个页面的
  ViewModel 生命周期。评论内进入登录页后，返回先回评论；在评论根页面返回才关闭覆盖层。
- 评论的顶部返回按钮与系统返回都走同一个局部导航根回调，底下媒体库的页面层级保持原样。
- Dialog 单独处理系统栏和键盘区域；评论底部不预留被覆盖的迷你播放器高度。
- Apple Music 样式的歌词模式使用可保存状态，并将返回交给播放器唯一的底层返回处理器：
  先回播放页，再次返回才收起。经典手机样式的歌词分页也采用相同的顺序。
- 歌曲百科及专辑/歌手跳转保留原有导航行为；本批没有将它们改成覆盖页。

## 验证

- 103 个测试集、664 项 JVM 测试通过，无失败或跳过。
- 真机回归 5 项通过：评论覆盖播放/歌词两种模式及局部返回栈 2 项、原生压缩 2 项、歌词切歌渲染 1 项。
- 真实界面逐步核对：底栏评论可进入，顶部返回回到原播放模式；歌词模式进入评论后返回仍为小封面歌词模式。
- 真实入口自动化试验受应用启动更新弹窗、歌词底栏自动隐藏及跨窗口节点状态影响，未作为通过证据；已移除该不稳定脚本，保留可重复的组件集成回归和真实手机检查。
- 调试包和测试包构建成功；最终正式包与安装结果见同批界面调整记录。
- 日志：`temp/player-comment-overlay-tests.log`（5 项通过）、`temp/player-ui-final-build.log`。
